# Cyrius v5.6.x Closeout — baseOS Update Checklist

> **Status**: Active backlog — **gate for all other port/start work** | **Opened**: 2026-04-23
> **Cyrius current**: v5.6.13 (linear-scan regalloc in flight)
> **Closeout target**: ~v5.6.22 per the Cyrius milestone table (remaining: v5.6.14 fused ops + O3–O6 phases)
> **At closeout, rewrite this doc in place** to reflect completion status, then archive under `archive/` or supersede with the v5.7.x-equivalent list.

**This is the active backlog gate.** Nothing else gets ported or started until this list clears. Fresh ports (bhava, aegis, aethersafha), new applications, new shared-crate scaffolds — all wait on this sweep completing. The rationale is simple: re-benchmarking upstream work against a moving compiler is expensive; doing it once at closeout with the arc's full optimization gains in-flight is much cheaper than doing it piecemeal, and new work started before the sweep just becomes more sweep surface.

This is a working punch list — not a report. Check items off as they complete. Add items as they're discovered. Mark blockers explicitly. When the v5.6.x arc closes, this file either (a) reads as "all items done, arc complete" and gets archived, or (b) names what didn't make it and hands off to a v5.7.x-equivalent doc.

**Background on why this exists:** [*Docs Go Stale Before the Commit*](../articles/docs-go-stale-before-the-commit.md) and [*Your Docs Are About to Rot*](../articles/your-docs-are-about-to-rot.md) argue that coordination documents should move with the code. This is one of them. Rewrite it in place as work completes — don't try to preserve historical state here; that's what git log is for.

## What "update" means per repo

For every repo below, when Cyrius v5.6.x closes:

1. Bump `cyrius = "5.6.X"` pin in `cyrius.cyml` to the closeout version
2. Run `cyrius deps && cyrius build && cyrius test` — must be clean
3. Re-run benchmarks (where applicable — noted inline below)
4. Update CHANGELOG with the closeout-pin bump
5. Update repo `VERSION` only if a user-facing change warrants it (pin bump alone is not a version bump)
6. Commit + tag

Per-repo verification: **always check the actual `VERSION` file and `cyrius.cyml` pin before acting on any single item below.** Drift caveat applies to this doc too — especially as items check off, the reader-state diverges from the write-state.
